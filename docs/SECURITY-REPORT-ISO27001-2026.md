## 1. תקציר מנהלים

בוצעה הערכת אבטחה מקיפה (Gap Assessment) לאפליקציית ניהול הקבלות Moses Caffee מול נספח A של תקן
ISO/IEC 27001:2022, ולאחריה יושמו בקרות טכניות לסגירת הפערים המהותיים. המערכת נבנתה מלכתחילה עם בסיס
אבטחה חזק (בידוד רב-דיירתי מלא ברמת מסד הנתונים, כותרות אבטחה מחמירות, הצפנת טוקנים, מחיקת GDPR), ולכן
ההערכה התמקדה בהעמקת הבקרות ולא בבנייתן מאפס.

**תוצאה כללית:** רמת בשלות **גבוהה**. כל הממצאים בדרגת סיכון גבוהה טופלו בגרסה 1.73.0. הסיכון המהותי היחיד
שנותר פתוח מנוהל באמצעות תיעוד ובקרות ארגוניות (יציאת נתונים לספקי בינה מלאכותית — ראו §7).

## 2. היקף ומתודולוגיה

**היקף:** כלל בסיס הקוד של המערכת — צד לקוח (React 19 / Vite 8), צד שרת (Cloudflare Pages Functions),
מסד נתונים (Supabase PostgreSQL + RLS + Auth), אחסון קבצים (Supabase Storage), ושרשרת האספקה (תלויות npm).

**מתודולוגיה:** סקירת קוד מלאה (read-only) בשלושה תחומים במקביל — שרת/API, מסד נתונים/RLS, וצד
לקוח/שרשרת אספקה — ומיפוי כל ממצא לבקרת Annex A הקרובה ביותר ולדירוג סיכון (קריטי/גבוה/בינוני/נמוך).
כל ממצא מהותי אומת ידנית מול הקוד לפני יישום. הערכות אוטומטיות שנמצאו שגויות תוקנו (ראו §4.1).

**מגבלות:** לא בוצעו בדיקות חדירה דינמיות (DAST) או בדיקות עומס; ההערכה מבוססת ניתוח קוד סטטי וסקירת
ארכיטקטורה.

## 4. טבלת ממצאים (Gap Assessment)

### 4.1 תיקוני אימות (הערכות אוטומטיות שנמצאו שגויות)
- **קובץ `.env` אינו ב-git** — נבדק (`git ls-files` + `.gitignore`); אין סודות במאגר.
- **אין audit log פעיל** — טבלת `audit_log` הייתה קיימת רק בקובץ מיגרציה נטוש
  (`supabase/migrations/20260609_multi_tenant.sql`, מודל `tenant_id` שהוחלף) שמעולם לא הופעל.
- **Session ב-localStorage** (ברירת המחדל של supabase-js), לא IndexedDB — נגיש-XSS אך ממותן ע"י CSP חזק.
- **OCR אינו מקומי** — ה-OCR הראשי הוא Google Gemini בענן; Tesseract הוא גיבוי בלבד.
- **כותרות אבטחה אוטומטיות** — `public/_headers` מועתק אוטומטית ל-`dist/` ע"י Vite בכל build.

### 4.3 בקרות קיימות מלכתחילה (לא נדרש תיקון)
RLS על כל הטבלאות (כולל `mail_connections` במצב deny-all) · פונקציות SECURITY DEFINER עם `search_path`
נעול · הצפנת AES-GCM לטוקני OAuth + חתימת HMAC על ה-state · bucket אחסון פרטי עם מדיניות per-user ·
CSP חזק (ללא unsafe-eval / inline-script) + HSTS preload + X-Frame-Options DENY (נבנים אוטומטית) ·
sourcemaps כבויים + הסרת console בפרודקשן · endpoint מחיקת חשבון (GDPR) · דפי משפט + גילוי סב-מעבדים ·
אין סודות במאגר הקוד.

## 5. בקרות שיושמו (גרסה 1.73.0)

### S1.1 — חיזוק בסיסי (Hygiene) · A.8.24 / A.5.18 / A.8.28 / A.8.15 / A.8.3 / A.8.2
- **השוואה קבועת-זמן** ל-`CRON_SECRET` (`constantTimeEqual` ב-`functions/api/_lib/auth.js`) — מונע דליפת
  מידע דרך תזמון תגובה.
- **`SUPERADMIN_EMAIL` כמשתנה סביבה** (עם fallback) במקום קידוד קשיח — `functions/api/admin/onboard.js`.
- **סניטציית שגיאות** — פרטי שגיאה מ-upstream (Supabase/Gemini/Anthropic) נרשמים בשרת בלבד; הלקוח מקבל
  קוד והודעה גנרית (`scan-receipt.js`, `chat.js`, `onboard.js`, `account/delete.js`).
- **הסתרת PII מלוגים** — נושאי מיילים הוחלפו ב-message_id (`gmailScan.js`, `mailIngest.js`).
- **`supabase_hardening_27001.sql`** — org_id ל-`suppliers` + טריגר מילוי + מדיניות org; אכיפת NOT NULL על
  `user_settings.org_id`; הגבלת EXECUTE על `current_org_ids()`/`fill_org_id()`; אילוץ `amount >= 0`.

### S1.2 — יומן ביקורת append-only עם שרשרת-Hash · A.8.15 / A.8.16 / A.8.7
- **`supabase_audit.sql`** — טבלת `audit_log` עם טריגר `BEFORE INSERT` (SECURITY DEFINER, pgcrypto SHA-256)
  המשרשר כל רשומה ל-hash של קודמתה → כל שינוי/מחיקה שוברים את השרשרת (tamper-evidence). נעילת ייעוץ
  (advisory lock) מונעת פיצול שרשרת. RLS: חברי ארגון קוראים בלבד; כתיבה = service-role בלבד; UPDATE/DELETE
  נשללו מ-authenticated.
- **`functions/api/_lib/audit.js`** — `writeAudit()` (best-effort; כשל לא שובר את הפעולה).
- **נקודות רישום:** הקמת לקוח, מחיקת חשבון, חיבור/ניתוק תיבת מייל.
- **תצוגה:** `/api/admin/audit` (בעלים בלבד) + לוח ב-`AdminPage` עם תג "שרשרת תקינה / שבר בשרשרת".

### S1.3 — הגבלת קצב פר-משתמש · A.8.12
- **`functions/api/_lib/rateLimit.js`** — מונה חלון-קבוע מבוסס Cloudflare KV, **fail-open** (אם ה-KV אינו
  מוגדר — לא חוסם). מוחל על `scan-receipt` (30/דק'), `chat` (20/דק'), `recategorize` (10/דק'),
  `mail/scan` (30/דק'), עם החזרת 429 + `Retry-After`.

### S1.4 — העברת תמונות ל-Storage מוצפן במנוחה · A.8.24
- סריקות מצלמה חדשות מעלות את הקובץ המקורי ל-bucket הפרטי (`storage_path`), ושומרות ב-DB **thumbnail קטן
  בלבד** (טקסט לא קריא). צפייה מלאה וייצוא לרו"ח מושכים את המקור דרך signed URL קצר-מועד. נפילה חיננית
  לאחסון inline אם ההעלאה נכשלת. `dataUrlToBlob` עוקף את חסימת ה-`data:` ב-CSP.

### S1.5 — אימות דו-שלבי (TOTP) לחשבון הבעלים · A.5.17 / A.8.5
- **`MfaCard`** (בהגדרות) — הרשמת TOTP (QR + אימות), כיבוי, טיפול חינני כשה-MFA אינו מופעל בפרויקט.
- **`MfaGate`** — שכבת step-up החוסמת את האפליקציה עד הזנת קוד, אך ורק כשקיים factor מאומת (אינרטית לכל
  השאר).
- **אכיפת שרת** — `/api/admin/onboard` דוחה `mfa_required` כשלבעלים יש factor מאומת אך ה-session ב-AAL1.

## 7. סב-מעבדים וסיכונים שאריתיים

### 7.1 רשימת סב-מעבדים (Sub-processors)
| ספק | תפקיד | נתונים | סטטוס DPA |
|-----|-------|--------|-----------|
| Supabase | DB, Auth, Storage | כל נתוני המערכת | DPA סטנדרטי — לאימות/תיעוד |
| Cloudflare | אירוח, Functions, KV | תעבורה, מטא-דאטה | DPA סטנדרטי — לאימות/תיעוד |
| Google (Gemini) | OCR תמונות קבלות | תמונות קבלות + טקסט | **נדרש DPA** — לאימות |
| Anthropic (Claude) | צ'אט עוזר עסקי | היסטוריית קבלות + ספקים | **נדרש DPA** — לאימות |
| Google / Microsoft | קריאת מייל (OAuth) | נושאים + קבצים מצורפים | scope קריאה-בלבד; אימות אפליקציה |
| בנק ישראל | שערי מטבע | קוד מטבע בלבד (ללא PII) | לא רלוונטי (אין PII) |

### 7.2 סיכונים שאריתיים (מקובלים / בניהול)
1. **יציאת נתונים לספקי AI (A.5.19–23):** תמונות קבלות ונתוני עסק מעובדים אצל Google ו-Anthropic. **בקרה:**
   מדיניות הפרטיות מגלה זאת במפורש; יש להשלים חתימת/תיעוד DPA מול שני הספקים. שקילת מזעור PII בצ'אט בעתיד.
2. **`xlsx@0.18.5` (A.8.8):** משטח תקיפה מוגבל — המערכת בעיקר **מייצאת** xlsx; קריאה רק בשחזור גיבוי עצמי של
   המשתמש. **המלצה:** מעבר ל-`exceljs` או הוספת ולידציה לקבצי ייבוא.
3. **Thumbnails ב-DB:** תמונות ממוזערות ≤256px (טקסט לא קריא) נותרות ב-DB — מוגן RLS + הצפנת-דיסק Supabase.
4. **קבלות ישן (base64):** רשומות שנוצרו לפני v1.72.0 עדיין מחזיקות תמונה מלאה ב-DB — מומלץ backfill מבוקר.
5. **Session ב-localStorage:** נגיש-XSS תיאורטית; ממותן משמעותית ע"י CSP ללא inline/eval-script.

## 8. מפת דרכים (המלצות עתידיות)
- השלמת/תיעוד DPA מול Google ו-Anthropic; שקילת מזעור PII בצ'אט.
- Backfill מבוקר של תמונות ישנות מ-base64 ל-Storage (אחרי גיבוי).
- החלפת `xlsx` ב-`exceljs`, או ולידציה קשיחה לייבוא.
- הרחבת MFA כאופציה לכלל הלקוחות (opt-in).
- דף offline ל-Service Worker (במקום 503 ריק) — זמינות (A.8.14).
- בדיקות חדירה תקופתיות (DAST) ובדיקת בידוד דיירים אוטומטית (Jest RLS).
